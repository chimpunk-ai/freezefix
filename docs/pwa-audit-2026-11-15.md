# PWA installation & distribution audit — 15 November 2026

Scope: can a person visit getfreezefix.com on their phone, install it, and use it like a native app without going through Google Play or the App Store? This document is the audit, the gaps that were found, and what shipped in response. All pins here are traced to specific files in the repo.

## Short answer

Yes — on main as of commit shipped alongside this doc. Chrome prompts people to install when it decides to, Safari supports Add to Home Screen, the service worker caches the shells people open first, nightly reminders are an opt-in shown to users only after they see the exact text, and the only private-data route anywhere on the site is the Fix AI chat (which only runs when a person presses send).

## Gaps found

1. **The service worker wasn't registered.** `PwaRegister` existed but nothing imported it. Without that import, `navigator.serviceWorker.register('/sw.js')` was never called, which means:
   - Chrome never showed its install banner.
   - Reminders couldn't subscribe (no active worker to subscribe through).
   - Nothing was cached for offline use.
   This is the single most load-bearing bug in the audit. Fixed by importing `PwaRegister` in `app/layout.tsx` (root layout) so every page registers on first visit.
2. **No install guide.** Chrome's own prompt is enough for some people; iPhone's Add to Home Screen needs explaining; both benefit from a bookmarkable page. Fixed by `app/install/page.tsx`, linked from the footer and from `components/InstallPrompt.tsx` on the Plans page.
3. **`InstallPrompt` not wired.** `/plans` now shows it in the right aside (`app/plans/page.tsx`), where someone's already thinking about committing to the product. It listens for `beforeinstallprompt` on Android and, on iOS Safari, shows the share-sheet instructions inline.
4. **Manifest was thin.** Rewritten to add `id`, `display_override`, `lang`, `dir`, `categories`, `shortcuts` (log, weeks, help as long-press shortcuts from the home screen), and `prefer_related_applications: false` (so Chrome doesn't suggest a Play Store listing we don't have).
5. **Install page wasn't precached.** `public/sw.js` now adds `/install` to its precache so a person reading the guide offline still gets it.
6. **Reminders server routes were absent** on `main` (they were parked during an earlier CF-deploy bisect). Restored: `app/api/push/{subscribe,unsubscribe,tick}`, `lib/push.ts`, `.github/workflows/push-tick.yml`, and `app/api/health/route.ts`. The service-worker–based subscription path (`lib/reminders.ts` ↔ `public/sw.js`) already landed in the previous round.

## What is not in scope — deliberately

- **No app-store listing.** The user's direction is "download ready as app ... leave payment thing right now". A Play Store or App Store listing requires a signing identity, store fees, review turnarounds, and commits the product to the store's rules on substance content. Not shipped. A Capacitor wrapper that loads the same URL remains an option when the store path is wanted; the PWA ships all the behaviour such a wrapper would carry.
- **Camera.** The product doesn't use a camera. If one is ever added (e.g. a scan-your-own-handwriting feature), permission would be requested at the moment of use, not up-front.
- **Payments.** Frozen by explicit instruction. `/plans` continues to say "free, for now" until payments are switched on. The install path works identically with or without payments.
- **Centrally-held accounts.** There are none, so "secure authentication" here means device-local: nobody to log in to, nothing on our server to breach. The only server-side identifier is a per-device cookie (`ff_device`) for the Fix AI quota count, and it maps to a hashed daily count rather than a profile.

## Platform notes

### Android (Chrome, Edge, Firefox)
- Chrome shows its own install prompt when the install criteria are met (manifest OK, served over HTTPS, SW registered). `InstallPrompt` catches `beforeinstallprompt` and shows a button; the user can also use the three-dot menu → "Install app".
- Manifest `shortcuts` surface as long-press options from the home-screen icon (Log, Weeks, Help).
- Web Push works in-browser on Android; `lib/reminders.ts` → `public/sw.js` → VAPID subscribe → `/api/push/tick` cron fires empty-payload pushes.

### iOS (Safari)
- Only Safari on iOS can Add to Home Screen. Chrome on iPhone uses Safari underneath and third-party browsers can't do it at all.
- `appleWebApp.capable: true` and `statusBarStyle: "black-translucent"` are emitted by Next from `app/layout.tsx`.
- Web Push on iOS requires the PWA to be installed first (iOS 16.4+). `components/InstallPrompt.tsx` and `components/RemindersControl.tsx` both check `needsHomeScreen()` (`lib/reminders.ts`) and tell the user plainly if the step is missing.
- Standalone mode drops the browser bar on next-open; `<meta name="apple-mobile-web-app-capable" content="yes">` is set via Next's metadata.
- Splash screen: iOS Safari composites one from the manifest's `background_color` and the apple-touch-icon until we ship pre-rendered `apple-touch-startup-image` PNGs for every device size. That is on the follow-up list (it's cosmetic, not blocking).

### Offline and updates
- `public/sw.js` precaches the handful of shells people open first (landing, app, weeks, settings, plans, install, help, privacy, terms, refunds, offline, manifest, icons).
- HTML navigations are network-first (so a logged-in app always sees the latest deploy) with the cache as a fallback.
- Static assets are stale-while-revalidate.
- `/api/*` is always live; nothing about chat or waitlist is ever cached.
- `VERSION` in `sw.js` is bumped (`v5-2026-11-15`) so clients clear the old cache on activate and pull the new bundle.

## Follow-ups (not required for installability)

- Pre-rendered `apple-touch-startup-image` PNGs for the current iPhone sizes, so the splash shown while iOS boots the PWA matches our brand instead of using the system composite.
- `shortcuts` icons: today they reuse `/icon-192.png`. Custom glyphs for Log / Weeks / Help would be nicer and are easy to add.
- A `screenshots` array in the manifest for Chrome's rich install UI (requires one phone-sized and one desktop-sized PNG; both exist elsewhere in the repo and could be referenced).
- Retiring `public/sw.js`'s manually-maintained precache list in favour of Workbox once the install flow is stable — not urgent, and the current list is small enough to maintain by hand.
